# 审核与发布

## 维护与内容的权限边界

`Frank-DingYC` 负责仓库维护与合并。按 PR 的完整文件差异决定是否需要他人批准：

| PR 范围 | 合并条件 |
| --- | --- |
| 不涉及 `content/` 的工具、工作流、配置、文档、样式等基础维护 | 必需检查通过后，维护者可以自行合并，无需他人批准 |
| 涉及 `content/` 的正文、图片、视频、目录、来源或其他文件 | 必需检查通过，并由相应产品的指定非作者业内审核者批准当前提交 |
| 同时包含基础维护和 `content/` 变更 | 按内容 PR 审核 |

新增、删除和重命名均属于变更；移出 `content/` 的文件仍按内容变更审核。`content/` 根目录公共文件由名单中任一指定非作者审核者批准。权限边界按目录判断：修改根目录 `README.md` 属于维护，修改 `content/` 内的 `README.md` 属于内容。

所有 PR 都保留 `build` 和 `industry-review` 必需检查。没有内容变更时，行业门禁自动满足；有内容变更时，检查作者声明及独立审核。维护者确认资格后，可以自行维护 `config/reviewers.json`；审核名单仍通过独立的维护 PR 更新。

## 何时成为正式内容

公开 PR 可以包含待审稿。只有通过本页流程并合并到 `main` 的内容，才收录为正式内容。公众号发送另由人确认。

1. 作者提供 Markdown、随文素材、`series.json` 和 `SOURCES.md`；CI 生成可审阅预览。
2. 至少一名对应产品的指定业内审核者核对原理、来源、定量口径、适用条件与图文；其本人必须是本文作者以外的人。以对 PR **当前 head 提交 SHA** 的 GitHub `APPROVED` 记录为准。审核者如参与写稿，应另请未参与写稿者审核。
3. 维护者检查手机阅读、图片、公式、篇幅和时长提示，并处理许可证与来源遗漏。
4. 构建、行业审核和分支保护全部满足后，由人合并。正文、技术图或指标变化需重新批准当前提交；纯样式变化另做视觉验收。

`config/reviewers.json` 是按产品维护的审核账号名单。维护者先人工确认业内经验和参与关系，再通过单独的配置 PR 添加；基础设施维护权限不代表行业审核资格。**名单为空的产品，内容变更会被门禁阻止合并**。不要用作者自己或机器人填充名单来消除失败。

自动门禁识别人类账号、排除 PR 作者及所涉系列 `authors` 声明的写稿账号、核对当前提交和产品名单，撤销或过期批准不生效。新增或修改正文须有作者声明。作者声明的完整性与账号真实性仍须人工核实；未知的历史作者不编造。AI、自查结果、格式通过、原始数据齐备均不能替代指定审核者。

## 信任边界

构建工作流用读取权限运行 PR 代码；审核门禁从默认分支执行受信任工具和名单，读取实时 PR 与审核记录，并给当前 head 写入 `industry-review` 状态。状态必须来自专用 GitHub App，分支保护绑定该 App 的数值 ID。GitHub Actions App 身份不能区分工作流，同仓库候选工作流可以申请写权限，因此不能把它作为行业批准状态的可信来源。

专用 App 的私钥仅存放在 `industry-review` Environment；该环境仅允许默认分支 `main` 的 Branch 部署，不能添加同名 Tag 或 PR 分支。审核工作流的 `GITHUB_TOKEN` 仍只读，由固定版本的官方 Action 获取限定本仓库、Contents/Pull requests 读取及 Commit statuses 写入的 App 令牌，不签出或执行待审代码。PR 的构建或审核信号完成后，会重新核对状态；信号本身不能批准文章。

一次性注册、环境保护、状态来源迁移与验收见 [专用审核 App 启用步骤](review-app-setup.md)。未安装 App、未配置私钥或未将规定状态绑定至其 ID，都不能视为身份隔离已经启用；凭证缺失时工作流失败，不回退至 Actions 令牌。组织管理员的配置权限仍属于信任边界。

`CODEOWNERS` 记录工作流、审核脚本、名单、历史台账、许可和品牌文件的维护责任，审阅请求为可选提示。主分支保留 PR、最新基线、构建、行业状态、讨论解决和线性历史要求，管理员也受保护，禁止强推和删除。全仓库通用批准数为 0，不要求 Code Owner 或最后推送者之外的人额外批准；`content/` 的独立审核由受信任行业门禁强制执行，新增提交须符合当前 SHA 的审核要求。仓库管理员的设置权限仍能影响保护，需由维护者约束。维护者应保持规定检查的名称和来源稳定。

## 两篇历史稿

2026-11-10 项目负责人确认功率分配前两篇的当前版本已通过既有业内审核。没有提供实际审核者、审核日期或历史 PR，故 `reviews/legacy.json` 将这些字段留空，并固定正文与逐项素材 SHA256；工具仅在全部匹配时展示历史审核标记。此例外仅覆盖这两个初始版本，不能扩展到新稿。后续修改走正常 PR。

## 审核清单

- 目标读者、问题和结论一致，标题不夸大结果。
- 来源能核查，解析、示意、仿真、实测区分清楚。
- 数值附单位、材料、波段、归一化、监视器和采样口径；跨案例比较条件成立。
- 图片与正文一致，素材权利说明齐备，审核所需材料可访问。
- 手机图表、公式与图注可读，长文和预计时长已说明。
