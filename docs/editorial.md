# 编辑与默认排版

新制作或重新生成的随文图片，图内中文、英文、数字、单位和图例统一使用小米 MiSans；按正文、说明和强调分别选用原始 Regular、Medium、Semibold。按图片最终展示尺寸检查多行文字的行距，以及标签与图形、边框和相邻标签的间距，不得挤压或重叠。空间不足时缩短文字、调整位置或扩大画布。导出后在手机参考宽度检查可读性，并在 `SOURCES.md` 记录字体来源与制作方式。历史图片仅在重新制作时适用。

## 可编辑图片

新制或重绘的示意图、流程图和数据图，以 **SVG 作为随文源图**，Markdown 直接引用同系列 `figures/*.svg`。保留文字为 `<text>` / `<tspan>`、图形为矢量对象；修改标签、配色、尺寸或数据后直接更新 SVG。图内字体继续使用 MiSans，字重为 400、500、600。不要将 PNG 包装进 SVG，也不要把可编辑文字转为轮廓。照片、软件截图、仿真场图等原生栅格素材按实际来源保留，历史已审图片在有依据重绘时再替换；替换仍须内容审核。

SVG 使用 UTF-8、有限且宽高为正的 `viewBox`，长短边比例不超过 32；单文件不超过 2 MiB、10000 个元素和 64 层嵌套。构建接受静态几何、文字、分组、渐变、裁剪、蒙版、标记和本文件片段引用；样式使用展示属性，或只包含展示属性的 `style`。导出时将样式表转换为展示属性，移除 DTD。脚本、事件、动画、HTML、嵌入栅格图、全局样式表和外部资源不属于支持范围。新图应在 `SOURCES.md` 记录矢量制作方式、字体来源和数据依据；生成脚本仍可选择保留在 `production/`。

本地、PR 和独立 HTML 将 SVG 作为经校验的内联矢量图显示，共用页面中的原始 MiSans；文字、线条和图形可缩放。公众号材料自动从这一渲染结果生成 PNG 上传副本，原始 SVG 与导出 PNG 的路径和哈希都进入素材清单。上传副本和手机长图只放在忽略的 `build/`，后续编辑以 SVG 为准。

## 主线与吸引力

每篇回答一个明确的工程问题：为什么需要它、怎样工作、条件和代价是什么、下一步如何验证。首屏给出目标读者、本文解决的问题及预计时长。GitHub 首页的逐篇阅读入口由 `tools/catalog.py` 生成同样的读者、问题、时长及长文提示；保留历史正文指纹，正式阅读目录以主分支为准。标题用具体机制或应用问题，承诺在文中兑现；小标题直接表达关键判断。每段围绕一个判断，先结论，再给证据和限制。结尾给一个相关案例或实践动作。

图片应帮助解释相邻问题：图注写“读到了什么”和必要条件，数据图保留坐标、单位、图例和来源。正文说明复杂图的关键数值或趋势，颜色之外辅以文字或线型。实测、仿真、解析估计和教学示意明确区分；不同材料、端口和采样条件的结果不直接排名。

扫描阅读和清楚的信息线索有助于读者找到内容；它们不保证公众号打开率或完读率。建议用目标读者试读和实际发布反馈调整标题、节奏与长文拆分。

## 共用样式

样式唯一实现在 `tools/style.css`：优先设备的系统界面字体（`system-ui`、`-apple-system`、`BlinkMacSystemFont`），中文依次匹配苹方、冬青黑体、微软雅黑、Noto Sans CJK SC；随后回退到小米 MiSans，最后使用通用无衬线字体。正文采用常规字重（CSS 400）、小标题及表头采用中等字重（CSS 500）、标题与强调采用半粗字重（CSS 600）；MiSans 分别使用 Regular、Medium、Semibold。这是本库的语义字重映射，不修改字体文件的原有权重或轮廓。正文 17px、行高 1.75，手机左右留白 22px，图注 14px。代码采用常见等宽字体，公式保留衬线字体及上下标。品牌蓝 `#0649AD` 用于链接和强调；正文与图注在白底达到普通文字 4.5:1 对比度基线。图片等比缩放，公式保留上下标。手机表格需要逐格可读；复杂表格拆为简表或分项说明后重审相关内容。

构建将官方原始 WOFF2 作为备用字体嵌入独立 HTML，等待实际使用的字体加载后再测量和截图。字体准备与许可见 [README](../README.md) 和[授权说明](rights.md#字体)。GitHub 的 Markdown 页面使用平台字体；公众号内联 HTML 不携带字体文件，按上述顺序使用设备可用的字体。更换字体后重新检查屏数、长文提示、表格和公式。

参考视口固定为 **390×844 CSS 像素**。工具测量正文区高度，包含标题、段落、图片、图注、公式和表格；不含编辑信息、页尾品牌和导航。通常 **6–10 参考屏**，短稿不强行扩写，长稿不自动截断。超过 10 屏时工具在首屏提示长文，编辑再判断拆篇、删去支线或保持完整。参考屏是本库编辑尺度，不是微信平台页数限制。

## 阅读时间

生成页首给“预计阅读 X–Y 分钟，实操另计”。这是编辑启发式估算：下限按汉字 450/分钟、拉丁词 200/分钟，加每图 10 秒、每公式段 5 秒；上限按汉字 250/分钟、拉丁词 120/分钟，加每图 25 秒、每公式段 12 秒，分别向上取整，至少相差 1 分钟。正文含表格与图注，图另加理解时间，公式段按 `p.eq` 计。

独立展示的等式、近似式及数值代入式统一使用 `<p class="eq">…</p>`；需要多行时在同一段内用 `<br>`。公式段内不要使用 Markdown 加粗，必要重点用 `<strong>`，上下标用 `<sub>`、`<sup>`。行内公式、解释性段落、图片中的公式和表格单元格不另按公式段加时。

这些系数是可解释的初始假设，未作为中文阅读速度研究结论。工程背景、公式难度、动画停留、实践时间与设备都会影响实际用时。先让目标读者手机试读；有足够样本再改估算模型，保留模型与测试同步。

## 公众号交付

构建产出独立 HTML、内联样式 `.wechat.html`、手机长图、素材 `.manifest.json` 和总报告。素材清单保留原文件与哈希；SVG 随文图与品牌自动生成 PNG 上传副本。公众号编辑器可能过滤标签、外链、内联样式和图片数据 URI，故 HTML 是排版交付物：在后台上传清单内的 `upload` 副本，原生栅格图仍使用 `path` 所指原图，替换图片来源，检查预览和真机效果后由人发送。清单不代表已上传；本库不调用群发接口。

## 调研依据

核对日期：2026-11-10。以下原则不等同微信特定平台硬限制。

- [NN/g：How People Read Online](https://www.nngroup.com/articles/how-people-read-online/)：在线扫描阅读与信息线索；不是微信公众号实验。
- [Gao、Li、Yu：Reading Time Prediction Model on Chinese Technical Documentation](https://research.utwente.nl/en/publications/reading-time-prediction-model-on-chinese-technical-documentation/)：字词、图片等因素影响技术文档访问时间；这里的系数不是该论文结论。
- [W3C：Contrast Minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)：普通文字 4.5:1 基线；17px 和行高是项目默认值。
- [W3C：Complex Images](https://www.w3.org/WAI/tutorials/images/complex/)：为复杂图片提供关系、关键数据和解释。
