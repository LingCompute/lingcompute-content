# 公众号版式规范与生成要求

本文件是公众号文章版式的唯一依据，面向人和 AI：写稿、改版式、生成配图前先读这里。

取值来自两篇已发布文章的**内联样式实测**，2026-11-13 逐项核对：

- 《图解无源光子器件 Vol.01丨一束光，怎么被"掰"成两路？》（2026-11-06）
- 《图解无源光子器件 Vol.02丨两条波导靠得够近，光就自己换手》（2026-11-12）

机器可读的那份是 `config/wechat-theme.json`：公众号稿的每个样式都从它查表生成。本文件解释「为什么是这些值」，主题文件决定「实际输出什么」。两处不一致时以主题文件为准，并由 `tests/test_wechat.py` 拦住文档漏写元素。

## 一、产物与唯一来源

同源两形，都从同一份 Markdown 生成：

| | 预览稿 `*.html` | 公众号稿 `*.wechat.html` |
| --- | --- | --- |
| 样式来源 | `tools/style.css` | `config/wechat-theme.json` |
| 生成方式 | 浏览器渲染 + 截图 | `tools/wechat.py` 查表内联，**不开浏览器** |
| 首屏编辑信息（产品/读者/阅读时长/参考屏/长文提示） | 保留 | 去掉 |
| 正文大标题 `h1` | 保留 | 去掉（微信标题栏已有） |
| 页首 | — | 「点击上方蓝字 关注我们」横幅 |
| 二级标题 `h2` | 文字 + 左侧竖线 | 斜切缎带横幅图 |
| 三级标题 `h3` | 16px（上面还有 `h2` 撑层级） | 18px（`h2` 已变成图，`h3` 顶上去） |
| 页尾 | 品牌 Logo、CC 许可、字体说明、审核状态、来源链接、导航 | 案例卡 → 签名卡 → 阅读原文条 |
| 用途 | 仓库审阅、GitHub 展示 | 粘进公众号编辑器 |

两份样式只共享一部分取值，共享项由 `tests/test_wechat.py` 逐条比对（正文、图注、图号胶囊、公式、表格）；**故意不同**的只有 `h3` 字号与列表符号处理，原因见下表与第三节。

公众号编辑器会过滤标签、外链与伪元素，所以**能在微信里存活的表现形式只有内联样式与图片**。凡是形状类装饰（斜切缎带）一律出图，不要用 CSS 伪元素或 `clip-path` 实现。

## 二、元素清单与取值

样式键名与 `config/wechat-theme.json` 的 `elements` 一一对应；改样式改主题文件，不要改 `wechat.py`。

| 元素 | 对应 | 取值 |
| --- | --- | --- |
| `root` | 整篇外层 `section` | 15px / 行高 1.75，`#2C4459`，外边距与内边距 0 |
| `p` | 正文段落 | 15px / 1.75，`#2C4459`，段距 `17px 0` |
| `h3` | 三级标题 | 18px 粗体 `#12263A`，左 4px `#2E7FD1` 竖线，内缩 13px，`36px 0 12px`，行高 1.5 |
| `strong` | 强调 | `#0B4C9C`，字重 600 |
| `a` | 链接 | `#0B4C9C`，无下划线，`overflow-wrap:anywhere` |
| `ul` / `ol` | 列表容器 | `16px 0`，`padding-left:0`，`list-style:none`（微信会吃掉符号） |
| `li` | 列表项 | `9px 0`，`padding-left:22px`；构建自动补符号（`ul` 补「·」，`ol` 补「1.」），源稿已手写则不重复 |
| `figure` | 图容器 | `30px 0 26px` |
| `img` | 随文图 | 宽 100%、`height:auto`、圆角 12px、投影 `0 6px 22px rgba(18,60,110,.1)` |
| `plate` | 载体图（关注横幅、案例卡、签名卡、CTA、章节横幅） | 宽 100%、`height:auto`，**不加圆角与投影**（图内底色满幅烘死，加圆角会切边） |
| `figcaption` | 图注 | 13px `#6C8195`，距图 11px，行高 1.75 |
| `fig-tag` | 图号胶囊 | 12px，`#EAF3FD` 底、`#0B4C9C` 字，圆角 5px，`1px 8px`，右距 7px，字距 .04em |
| `eq` | 公式卡片（`<p class="eq">`） | 16px 衬线 `#12263A`，居中，`#F6FAFE` 底，左 3px `#9EC4E8`，圆角 `0 10px 10px 0`，内边距 `15px 18px 14px`，行高 2.05，字距 .01em |
| `note` | 免责/脚注（`{: .note }`） | 14px 斜体 `#6C8195` |
| `greek` | 希腊字母 | 衬线斜体 |
| `table` | 表格 | 宽 100%、`border-collapse`、`24px 0 20px`、14.5px / 1.7、`font-feature-settings:"tnum"` |
| `th` | 表头 | 13px 600 `#0B4C9C`，`#EAF3FD` 底，`9px 11px`，下边 1.5px `#CBE0F5`，字距 .03em，左对齐 |
| `th-nowrap` | 表头不折行 | 仅当表格 ≤ 3 列时附加 `white-space:nowrap`；列多时自动放弃，避免手机宽度溢出 |
| `td` | 单元格 | `9px 11px`，下边 1px `#EDF3F9`，`#2C4459`，顶对齐，`overflow-wrap:anywhere` |
| `td-zebra` | 隔行底色 | 偶数行 `#FAFCFF` |
| `td-last` | 末行 | 去掉下边框 |
| `blockquote` | 引用 | `24px 0`，`4px 18px`，左 3px `#2E7FD1`，`#F3F7FC` 底 |
| `pre` | 代码块 | 13px 等宽，`#F3F7FC` 底，内边距 14px，`pre-wrap` |
| `code` | 行内代码 | 13px 等宽 |
| `follow` | 关注横幅容器 | 居中 |
| `banner` | 章节横幅容器 | 居中，`margin-top:40px`，`margin-bottom:0` |
| `case` | 案例卡容器 | 居中，`margin-bottom:0` |
| `plate-section` | 签名卡 / CTA 容器 | 居中 |

品牌蓝 `#0B4C9C` 用于链接与强调；签名卡内标识沿用原始 `#0649AD`，不改图。

表格不再画竖线：表头一条 1.5px 的深色线、行间 1px 浅线、隔行浅底、末行收边——这是 Vol.02 起定下的形态，预览稿同步采用（手机断点下字号收到 13px、内边距收到 `8px 6px`，避免三列在 390px 宽度里挤成一列一个字）。

## 三、微信会吃掉什么

这几条不是风格问题，是平台行为，写稿与改版式都要按它办：

1. **class 不生效**：发布稿里所有 `class` 都被移除，样式全部写在 `style` 上；构建后仍出现 `class=` 即视为失败。
2. **列表符号消失**：两篇发布版里 `ul` 都被编辑器改成 `list-style:none`。Vol.02 是人工在正文里补「·」，Vol.01 干脆没有符号。现在由构建统一补：`ul` 补「·」、`ol` 补「1.」，源稿已经写了符号就不重复——不要指望 `list-style` 与 `::before`。
3. **伪元素与 `clip-path` 失效**：斜切缎带只能出图（`tools/banner.py`）。
4. **外链图片被拦截**：随文图必须是 `data:` URI；构建已把栅格图与 SVG 的 PNG 副本都内联。
5. **正文 `h2` 不可选**：二级标题一律换成横幅图；`h2` 残留即失败。
6. **粘贴时编辑器可能给文字包一层 `span`**，把字号压回正文（Vol.02 的 `h3` 就出现过）。粘贴后目检三级标题与公式卡片，必要时在编辑器里把该段字号改回 18px / 16px——这一条构建拦不下。

## 四、两篇发布版的差异与取舍

两篇不是同一版式，冲突处取较新的 Vol.02：

| 项 | Vol.01（11-06） | Vol.02（11-12） | 采用 |
| --- | --- | --- | --- |
| 公式 | 16px 加粗行内文字 | 16px 衬线卡片（浅底 + 左侧细线 + 右圆角） | Vol.02 |
| 脚注 | 12px 斜体 | 14px 斜体 | Vol.02 |
| 表格 | 全网格 1px 边线 | 只留横线 + 表头浅蓝 + 隔行浅底 | Vol.02 |
| 列表符号 | 无（被微信吃掉） | 正文写「·」补符号 | Vol.02 |
| 三级标题 | 元素 18px，被编辑器包成 16px | 元素 18px，被编辑器包成 15px | 声明 18px，粘贴后目检 |
| 正文 | `p` 17px + 内层 `span` 15px | 同上 | 净字号 15px |

Vol.02 的 `p` 是 17px、里面的文字被包成 15px，两者相抵后正文仍是 15px——这是编辑器产物，不是设计值，不要照着写 17px。

## 五、章节横幅

正文每个 `##` 标题在公众号稿里换成一张 1080×159 的斜切缎带图，由 `tools/banner.py` 现场绘制（微信里伪元素活不下来）。

- 画布 1080×159 透明底；缎带高 78、斜切 41（底边相对顶边左移）、居中
- 填充为横向渐变 `#0C6DDB` → `#074FB5`；文字纯白、MiSans Semibold 52px
- 缎带宽度 = 文字宽 + 2 × 内边距，内边距 `40 + max(0, 文字宽 − 464) × 0.15`，最小缎带宽 370
- 浅蓝层：同色 29% 不透明，倾斜 1.2° 垫在缎带后；两端各一个 22×22、斜切 11 的小色块
- 文字宽超过 940 时先缩字号（下限 40），仍放不下就折两行并加高画布；两行仍放不下时构建报错，要求改写标题（约 40 字以上）

横幅图按标题文案缓存，同一标题只画一次；预览稿保留可选中文字，只把竖线样式对齐上表——不要在两处分别维护标题文案。

## 六、页首与页尾

全部为图片，与正文同宽、不加圆角、不加投影。

1. **关注横幅** `assets/brand/wechat-follow.png`（1080×359），每篇置顶复用。属载体装饰，不进正文源稿。
2. **案例卡**（1080×334，`tools/banner.py` 合成）：数据来自 `series.json` 每篇的 `case` 字段——`title` 案例名、`qr` 二维码图、`url` 目标页。缺 `case` 即跳过；横向比较类篇目本来没有单一配套案例。版式：`#ECEBEC` 底、圆角 16px，二维码白底面板 210 见方、左起 77、垂直居中，标题 46px Semibold `#1A1A1A`，副题 44px Regular `#333`，文字左起 353。
3. **签名卡** `assets/brand/wechat-signature.png`（1080×1162），全站固定：注册二维码、官网与试用申请、商务与定制咨询、品牌标识与主张。
4. **阅读原文条** `assets/brand/wechat-cta.png`（1080×95），全站固定。

品牌载体图以原始 PNG 保存，不重绘、不放大、不二次编码，构建时只做等比缩放；哈希记入每篇 `manifest.json` 的 `brand_assets` 段。

## 七、配图

- **源图格式**：示意图、流程图、数据图以 **SVG 作为随文源图**，Markdown 直接引用同系列 `figures/*.svg`；照片、软件截图、仿真场图等原生栅格素材保留 PNG。约束（`viewBox`、2 MiB、10000 元素、64 层嵌套、禁止脚本与嵌入栅格）见[可编辑图片](editorial.md#可编辑图片)。构建把 SVG 内联渲染，导出时按 642 CSS 像素宽、2 倍像素密度栅格化成 PNG 上传副本，`manifest.json` 里同时记 `path` 与 `upload` 及其哈希。
- **字族**：与正文同族，matplotlib 用 MiSans（Regular / Medium / Semibold 按语义字重匹配）。字体文件只留在本地缓存，PNG 是排版后的作品，SVG 以字族名引用而不嵌字体。
- **场图必须按真实坐标绘制**：Tidy3D 在波导附近加密网格（y 步长 0.029–0.071 μm 不等），`imshow(extent=[y.min(), y.max()])` 会按线性范围拉伸，把光场整体推开约 0.5 μm，看上去就是"场浮在器件上面"。用 `figure_style.field_panel()` 先重采样到均匀网格再画。
- **文字不压线**：标注一律放在空白区，引线只连到被测区域；端口标签放在波导外侧；同一高度上的多个标注要错开高度，避免互相叠字。曲线图的刻度说明放在曲线之上或之下的空白带，不要贴着峰顶或谷底。
- **图注写读到了什么**：数据图保留坐标、单位、图例与来源；示意、解析、仿真、实测分开标注，不同条件的读数不排名。

## 八、给 AI 的硬性要求

写稿、改版式、重绘配图时按此执行，逐条可核对：

1. 先读本文件与 `docs/editorial.md`；改样式前先取发布版实际取值，不要从旧模板推断。
2. **公众号稿改 `config/wechat-theme.json`，预览稿改 `tools/style.css`**；`wechat.py` 与 `build.py` 只管结构与流程，不写死颜色或字号。两份共享取值由测试比对，改一处要同步另一处。
3. 新增装饰形状先问"微信会不会过滤"：会，就出图；不会，才用 CSS。
4. 公众号稿的内容差异（去 h1、去编辑信息、去许可与导航、加页首页尾、`h2` 换横幅）由构建自动处理，不要手工裁剪 HTML。
5. 生成后必须执行：`python -m unittest discover -s tests`、`python tools/build.py --check`、完整构建，并在 390×844 视口检查截图（无横向溢出、横幅与签名卡完整、图注胶囊正常），再目检 `.wechat.html`（三级标题字号、公式卡片、表格三列是否仍在一屏内）。
6. 改了随文素材要同步 `SOURCES.md` 与 `series.json`；素材字节变化会让 `historical_review_matches` 变 false——这是审核指纹的正常反应，**不要**自行修改 `reviews/legacy.json` 掩盖。
7. 重绘示意图、数据图时出 SVG 源图，场图与截图保留栅格；不要 PNG 套壳成 SVG，也不要把可编辑文字转成轮廓。
8. 不把字体文件、`.cache/`、`build/` 提交进仓库；不重绘或放大品牌载体图；不把发布版截图当作素材。
9. 长文超过 10 参考屏要提示读者，并在 PR 里说明是拆篇还是保留。

## 九、机器校验与 CI 成本

公众号稿不再走浏览器 `computed style`，所以版式可以在秒级验证：

| 命令 | 覆盖 | 是否需要 Chromium |
| --- | --- | --- |
| `python -m unittest discover -s tests` | 主题完整性、文档与主题一致、预览 CSS 与主题一致、结构改写、表格斑马纹、`audit()` 规则 | 否 |
| `python tools/build.py --check` | 源稿可读性 + 每篇文章的公众号稿结构与内联样式 | 否 |
| `python tools/wechat.py --spec` | 打印当前主题的全部内联样式，用于和发布版对表 | 否 |
| `python tools/wechat.py --check build/…wechat.html` | 检查已生成的发布稿 | 否 |
| `python tools/build.py` | 预览截图、SVG 栅格化、manifest、页首页尾 | 是 |

构建侧的两处效率约定：

- **SVG 一次性栅格化**：所有文章的矢量图放进同一个页面、同一轮浏览器里出图，不随篇数线性变慢。
- **预览只渲染一次**：先按占位符渲染并量高度，再用 `innerHTML` 回填参考屏数与长文提示，不重新加载整页。

构建能自动拦下的：缺图注替代文字、`h2` 超过 18 字、参考视口横向溢出、`series.json` 与目录不一致、素材路径越界、SVG 不合规或与渲染出的图数量不符、公众号稿残留 `class`/`h2`/固定像素宽度/微信不支持的声明。构建拦不下的（必须人眼过）：文字是否压线、标注是否读得通、图片在手机宽度下是否还看得清、粘贴进编辑器后的字号、与发布版的观感是否一致。

## 十、变更流程

- 版式或素材的改动走 PR；涉及 `content/` 的改动按 `docs/review.md` 由指定业内审核者批准，AI 与构建通过都不替代该批准。
- 样式改动即使不影响正文，也要附手机截图做视觉验收；动到主题文件时同时贴一张 `.wechat.html` 的截图。
- 发布版是基准：发布版与源稿出现差异时，先记差异清单交编辑与审核者判断，不要顺手改正文。
